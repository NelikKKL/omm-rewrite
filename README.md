# OMM (Open Math Model)

[READ in English](README.EN.md)

**OMM** — сверхлегкий формат 3D-моделей и автономный движок на **Rust**, скомпилированный в **WebAssembly**, с отрисовкой на **WebGL2**. Для быстрой интеграции 3D-графики в веб-проекты без сторонних зависимостей.

> **v4.0** — движок переписан с нуля: **парсер → байт-код → виртуальная машина → viewer (WebGL2)**. Формат `.omm`, его синтаксис, WASM/JS API и тег `<omm-model>` остались прежними: старые модели загружаются как раньше, а прежняя JS-обёртка совместима по API (оговорки — в разделе [«Что изменилось»](#что-изменилось-по-сравнению-с-3x)).

## 📦 Подключение

### Локально
Соберите проект (см. [Сборку](#-сборка-и-проверка)) или скачайте артефакт `pkg` из GitHub Actions и положите в одну папку:
- `omm-component.js`
- `omm_core.js`
- `omm_core_bg.wasm`

```html
<script type="module" src="./omm-component.js"></script>
```

> ⚠️ Нужен локальный HTTP-сервер (Live Server, `python -m http.server` и т.д.) — браузеры блокируют WASM/модули с `file://`.

### CDN
Если вы публикуете папку `pkg/` (например, коммитом в репозиторий), её можно подключать через jsDelivr — `omm_core.js` и `omm_core_bg.wasm` подтягиваются автоматически, они лежат рядом:

```html
<script type="module"
  src="https://cdn.jsdelivr.net/gh/NelikKKL/OMM-model@v4.0.0/pkg/omm-component.js">
</script>
```

> Workflow в репозитории **только собирает** проект и кладёт `pkg/` в артефакт — ничего не коммитит и не публикует.

## 🚀 Быстрый старт

```html
<!-- Автовращение -->
<omm-model src="model.omm" autorate></omm-model>

<!-- Полный контроль (мышь + тач + зум) -->
<omm-model src="model.omm" freer></omm-model>

<!-- Модель прямо в теге -->
<omm-model autorate>
  cube3
  color(80, 140, 255)
  scale(2)
</omm-model>
```

### Атрибуты `<omm-model>`

| Атрибут | Описание |
| :--- | :--- |
| `src` | Путь к файлу `.omm`, `.glb` или `.obj`. |
| `autorate` | Бесконечное автовращение модели. |
| `freer` | Вращение мышью/тачем + пинч-зум + панорамирование (ПКМ / средняя кнопка). |

События: `omm-load` (модель разобрана), `omm-error` (ошибка; текст показывается и поверх холста). Свойство `el.engine` — доступ к `OmmEngine`.

## 📝 Синтаксис `.omm`

Файл `.omm` — текстовый документ. Каждая фигура начинается с ключевого слова. Строки, начинающиеся с `//`, — комментарии.

### 1. Геометрия

| Ключевое слово | Описание |
| :--- | :--- |
| `cube3` | Стандартный куб. |
| `cube3 : 4` | Плита (высота уменьшена в 4 раза). |
| `pyramid3` | Пирамида. |
| `sphere3` | Сфера. |
| `cylinder3` | Цилиндр. |
| `triangle3` | Плоский треугольник. |
| `image3` | Плоскость с текстурой (рисуется, когда текстура загружена). |
| `mesh3` | Произвольная (сложная) геометрия — см. раздел ниже. |

### 1.1. Произвольная геометрия `mesh3`

`mesh3` — не примитив, а контейнер для любой треугольной геометрии: импортированной из `.glb`/`.obj` или описанной руками. Освещение для `mesh3` считается по нормали каждой грани (плоский шейдинг), а не по индексу грани, как у примитивов — поэтому сложные формы выглядят корректно из любого ракурса.

**Вручную** (для несложных кастомных форм):

```
mesh3
verts(0 -50 0, 50 50 0, -50 50 0, 0 -50 100)
tris(0 1 2, 0 3 1, 0 2 3, 1 3 2)
color(220, 120, 60)
```

- `verts(x y z, x y z, ...)` — список вершин (через запятую и/или пробел).
- `tris(i j k, ...)` — список треугольников (индексы вершин, с нуля).
- `uvs(u v, ...)` — необязательные UV-координаты (0–1) для текстуры, по одной паре на вершину.

Списки можно переносить на несколько строк, внутри допустимы комментарии `//`:

```
verts(
  0 -50 0,    // верх
  50 50 0,
  -50 50 0
)
```

**Автоматически** — конвертеры упаковывают геометрию в компактный base64 и пишут её в `data(...)`:

```
mesh3
data(AAAAAA...)
color(200, 200, 200)
texture(data:image/png;base64,...)
```

`data(...)` не предназначен для ручного редактирования — это бинарный формат, который генерируют `obj_to_omm`/`glb_to_omm` (см. ниже). К `mesh3` применимы все обычные трансформации (`x/y/z`, `scale`, `rr/ru`, `animation`, `mono()`), кроме асимметричной деформации (`ur/ul/...`).

Некорректная геометрия не ломает сцену: треугольники с несуществующими вершинами отбрасываются, а UV, число которых не совпадает с числом вершин, игнорируются (в консоль выводится предупреждение).

### 1.2. Импорт `.glb` и `.obj`

Достаточно указать `src` с нужным расширением — конвертация в `mesh3` происходит автоматически прямо в браузере, без серверной обработки:

```html
<omm-model src="model.glb" autorate></omm-model>
<omm-model src="model.obj" freer></omm-model>
```

| Формат | Что переносится | Ограничения |
| :--- | :--- | :--- |
| `.glb` (бинарный glTF) | Вся иерархия узлов (трансформации запекаются в вершины), цвет `baseColorFactor`, встроенные PNG/JPEG-текстуры | Только самодостаточный `.glb` (не `.gltf` + внешние файлы); только режим `TRIANGLES`; скелетная анимация и морф-таргеты не переносятся |
| `.obj` (Wavefront) | Вершины, UV, треугольники/n-угольники (триангулируются веером) | `.mtl`-материалы не парсятся — цвет по умолчанию серый, добавьте `color()`/`texture()` в результат вручную |

Части `.glb` с одинаковым материалом (цвет + текстура) объединяются в один `mesh3`: встроенная картинка пишется один раз, а не по копии на каждую часть.

Чтобы один раз сконвертировать файл и сохранить результат как обычный `.omm`, можно вызвать конвертер напрямую:

```js
import init, { obj_to_omm, glb_to_omm } from './omm_core.js';
await init();

const ommText = obj_to_omm(await (await fetch('chair.obj')).text());
// или:
const bytes = new Uint8Array(await (await fetch('chair.glb')).arrayBuffer());
const ommText2 = glb_to_omm(bytes);
```

Обе функции бросают исключение со строкой-описанием, если файл повреждён или формат не поддерживается.

### 2. Трансформации

```
x(n)     y(n)     z(n)     — позиция (y идёт вверх, отрицательные значения поднимают)
scale(n)                    — масштаб (по умолчанию 50 пикселей на грань)
rr(deg)                     — поворот вправо (ось Y)
ru(deg)                     — поворот вверх  (ось X)
```

Свойства можно писать по несколько в строке и в той же строке, что и имя фигуры: `sphere3 x(40) color(255,0,0)`.

### 3. Анимация

```
animation(x0 y0 z0, x0 y200 z0)   — список ключевых точек через запятую
animation(y200, y0)                — можно указать только нужные оси
```

В ключевых точках поддерживаются `x`, `y`, `z`, `rr`, `ru`.

### 4. Асимметричная деформация

Растяжение сторон (работает для всех примитивов, кроме `mesh3`):

```
ur(n)  ul(n)   — вправо / влево (ось X)
uu(n)  ud(n)   — вверх  / вниз  (ось Y)
ug(n)  um(n)   — вперёд / назад (ось Z)
```

### 5. Цвет и текстуры

```
color(R, G, B)                         — цвет заливки, 0–255
texture(https://site.com/img.png)      — внешняя ссылка
texture(data:image/png;base64,iVBOR…)  — встроенный Base64
```

Текстура накладывается на все грани фигуры автоматически. Пока картинка не загрузилась, фигура рисуется своим цветом.

> ⚠️ **WebGL требует CORS**: картинка с другого домена должна отдаваться с заголовком `Access-Control-Allow-Origin` (его присылают GitHub raw, jsDelivr, imgur и большинство CDN). Встроенные `data:`-текстуры и картинки с вашего домена проблем не имеют. Если загрузить текстуру не удалось, фигура остаётся одноцветной, а причина попадает в `engine.warnings()` и консоль.

### 6. Группировка `mono()`

Объединяет несколько фигур в группу с общим преобразованием:

```
mono(
  x(0) y(0) scale(1)   ← группа-трансформ (необязательно)

  cube3
  color(150, 150, 150)
  y(200)

  sphere3
  color(200, 100, 50)
)
```

Преобразование группы (`x y z scale rr ru`) применяется ко всем фигурам блока один раз при загрузке; `animation()` относится к конкретной фигуре. Блоки `mono()` можно вкладывать друг в друга.

## 🏗 Архитектура

```
 текст .omm ──▶ parser ──▶ байт-код ──▶ vm ──▶ простые данные ──▶ viewer ──▶ WebGL2
                  │           │          │                          │
        только синтаксис   контракт   строит мир:           ничего не знает о формате,
        (ничего не строит) (bytecode) объекты, группы,      байт-коде и VM: рисует
                                      меши, анимация        треугольники и матрицы
```

| Модуль | Роль |
| :--- | :--- |
| `parser` | Читает текст и **только эмитит инструкции**. Не создаёт объектов и геометрии, не применяет групповые преобразования. Никогда не паникует: всё подозрительное — в `warnings` (с номерами строк). |
| `bytecode` | Набор инструкций (`SHAPE`, `X`, `COLOR`, `GROUP_BEGIN`, `KEYFRAME`, …) и контейнер `OMMB` (`Program::to_bytes` / `from_bytes`) — скомпилированную сцену можно кэшировать (`compile()` → `OmmEngine.load_bytecode()`). |
| `vm` | Исполняет байт-код: создаёт объекты, применяет свойства, считает `mono()`, собирает меши, двигает анимацию. Любой байт-код (обрыв, неизвестные инструкции, неверные индексы) даёт предупреждения, но не панику. |
| `viewer` | Принимает треугольные сетки, экземпляры (матрица + цвет + текстура) и камеру. Непрозрачное рисуется с буфером глубины; текстуры с прозрачностью — вторым проходом, от дальних к ближним. |
| `camera` | Состояние камеры, управление и матрица «вид × проекция», в точности воспроизводящая проекцию 3.x. |
| `convert` | Импорт `.obj` / `.glb` в текст `.omm`. |

Всё, кроме тонкого слоя `web` и WebGL-бэкенда, **не имеет зависимостей** и тестируется обычным `cargo test`. Код проекта не содержит `unsafe` (`#![deny(unsafe_code)]`; единственное исключение — код, который генерирует сам `wasm-bindgen`).

### Что изменилось по сравнению с 3.x

| | 3.x | 4.0 |
| :--- | :--- | :--- |
| Рендер | Canvas 2D, сортировка граней (painter's algorithm) | WebGL2, буфер глубины — пересекающиеся объекты рисуются корректно |
| Геометрия | пересчитывалась каждый кадр | таблицы фигур строятся один раз и разделяются между объектами; освещение мешей считается при загрузке |
| Контуры граней | `stroke` на каждую грань | рисуются в шейдере (≈1 px, прозрачность 0.15), `set_outline(0)` отключает |
| Парсер | переписывал текст, затем разбирал построчно | один проход → байт-код; списки на несколько строк; вложенные `mono()` |
| «За спиной» камеры | рисовалось зеркально | корректно отсекается |
| Паники/зависания | возможны (циклы в glTF, огромные размеры, `NaN`) | исключены: проверки границ, лимиты, обход графа с защитой от циклов |
| Hi-DPI | — | `set_pixel_ratio()`: холст чётче, размер модели тот же |

Совместимость: API `OmmEngine` и тег `<omm-model>` не менялись. Что стоит знать при обновлении:

- Нужен **WebGL2** (поддерживается всеми современными браузерами). Если его нет, `setup()` бросает исключение, а компонент показывает сообщение.
- Внешние текстуры должны отдаваться с CORS (см. выше).
- Свойства, написанные *после* закрывающей `)` блока `mono()`, больше не прикрепляются к его последней фигуре, а игнорируются с предупреждением.
- Асимметричная деформация (`ur/ul/…`) работает и у `cube3` (в 3.x документация это отрицала, хотя код деформировал куб).

## 🔌 API `OmmEngine`

| Метод | Описание |
| :--- | :--- |
| `new OmmEngine()`, `setup(canvas)`, `resize(w, h)` | Создание, подключение холста (WebGL2), размер холста. |
| `parse(text)` | Заменяет сцену. Камера сохраняется. |
| `pending_textures()`, `set_texture(src, img)` | Какие картинки нужны сцене; передача загруженной картинки. |
| `step()`, `auto_rotate()`, `render()` | Тик анимации, шаг автовращения, отрисовка кадра. |
| `drag(dx, dy, mode)`, `zoom(delta)`, `pinch_zoom(z0, d0, d)` | Управление камерой (`mode` 0 — вращение, иначе — панорама). |
| `has_animation()`, `focal()`, `camera_z()` | Состояние. |
| `obj_to_omm(text)`, `glb_to_omm(bytes)` | Конвертеры (функции модуля). |
| **новое:** `warnings()` | Замечания к последней сцене (опечатки, битые данные), с номерами строк. |
| **новое:** `set_outline(a)`, `set_pixel_ratio(r)` | Прозрачность контуров (0 — выключить); отношение физических пикселей холста к логическим. |
| **новое:** `compile(text)`, `load_bytecode(bytes)` | Компиляция в байт-код и загрузка скомпилированной сцены. |

## 🔧 Сборка и проверка

Требования: [Rust](https://rustup.rs/) + [wasm-pack](https://rustwasm.github.io/wasm-pack/).

```bash
wasm-pack build --release --target web --out-dir pkg
cp js/omm-component.js pkg/
```

Артефакты появятся в `pkg/`. Собранный WASM использует `bulk-memory` и saturating-преобразования float→int (их по умолчанию генерирует современный Rust; поддерживаются всеми актуальными браузерами) — нужные флаги для `wasm-opt` уже прописаны в `Cargo.toml`.

Проверки:

```bash
cargo test                          # парсер, байт-код, VM, камера, конвертеры, сквозные тесты
python3 tools/check_shaders.py      # шейдеры и порядок вызовов GL в настоящем WebGL2 (headless Chromium)
python3 tools/check_component/run.py  # JS-компонент: ввод, текстуры, DPR, ошибки (мок ядра)
```

Для двух последних нужен `pip install playwright && playwright install chromium`.
